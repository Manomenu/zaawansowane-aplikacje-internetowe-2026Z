## What was done

- **`README.md`** rewritten: what the app shows and why (forest conditions for mushrooms), the public address (stated as being deployed: `/api/health` on the host did not answer 200 when checked), what a reader and an administrator can do, a sample printout, where the data comes from (the sensor emulator, Open-Meteo with CC BY 4.0), what it does not know, a short course note and one link to the developers' document.
- **`docs/development.md`** (new): requirements, the three ways to run, everyday commands and checks (`just` recipes checked against the `justfile`), where things are, links to AGENTS.md, design, requirements, the generator and `docs/spec/`.
- **`docs/img/`**: `dashboard.png`, `print.png`, `print-table.png`, `phone.png`, rendered from the local container stack with Playwright (printouts: `emulateMedia print`, `page.pdf` A4 landscape, `pdftoppm -r 80`). Five leftover test series on that stack (junk names) were unchecked, then the filter panel hidden, so the images show only the 12 sample series.
- **`AGENTS.md`**: the intro and the "What lives where" table point to `docs/development.md`.

## Why this way

- Screenshots come from the real stack, not mocks: they show what a user sees. They are committed PNGs (already marked binary in `.gitattributes`) and are not regenerated by the gate (YAGNI; they change rarely).
- The filter panel is hidden in the images, because the stack still held test series whose names would clutter it; hiding it was simpler than deleting the owner's data.
- No command blocks in the README: the one place a user needs a command, the generator, is a link to its own README.

## How to verify

- `./scripts/.internal/requirements.sh`
- Open `README.md` on GitHub or in an editor preview: the four images load and the links to `docs/development.md`, `docs/requirements.md` and the generator's README resolve.
- `just --list` shows every recipe named in `docs/development.md`.
